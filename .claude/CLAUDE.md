# コミュニケーション
- 日本語で応答する（コード・変数名は英語）
- 簡潔に回答し、自明な説明は省略する
- 目的・ゴールを明らかにしてから着手する
- ユーザの期待を忖度して推論で決めない。先に期待成果のギャップを埋めること。
- 複雑なタスクでは実装前に計画を提示し、承認後に着手する

# Git規約
- プロジェクト固有のGit運用ルールがない場合はユーザに確認を取る
- ルールが提示されていない場合は、確認なしにブランチの作成・コミット・プッシュをしない
- コミットメッセージに自身の情報を記載しない
- Conventional Commits形式、本文は日本語（例: `feat: ユーザー認証にOAuth2を追加`）

# 作成・編集・削除
- 既存のREADME・ドキュメント群は変更に応じた整合性を取ること。ただし、許可無く新規作成しない。
- プログラムコードを確認なしに作成・削除・コメントアウトしない
- 既存の動作するコードを理由なくリファクタリングしない
- リポジトリや作業ディレクトリへ勝手に計画・設計書等を追加しない。指示がない場合は、 /tmp 配下に一時的に計画を作成する
- ソースコードへのコメントやドキュメントに作業ログを書かない（以前は～だった、など）。

# 学習・知識の蓄積
- 再利用可能な知識は与えられたツールを活用して記録する
- 再利用可能な手順は都度スキル化を検討する
- 車輪の再発明はせず、既存のツール・スキルで解決可能な知恵は再利用する

# 成果物と表現
- 情報の量より品質を重視する
- 造語やユニークな表現を避ける
- 定式化や図表（Mermaid）などを用いて理解しやすく解釈のブレがないように気をつける
